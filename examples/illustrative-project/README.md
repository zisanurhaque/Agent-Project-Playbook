# Pantry (illustrative and fictional)

> **This project does not exist.** Everything in this directory is invented: the application, the people, the dates, the files, and every event described. Nothing here is a test result, a measurement, a user report, or a deployment outcome. This example exists to show the structure of project documentation, and nothing else.

Pantry is a small self-hosted web application used by two people in one household to keep track of what food is in the house and when it expires. The intended user is someone who cooks at home and loses track of what is in the freezer.

## The documents here

| File | What it is |
| --- | --- |
| [project-brief.md](project-brief.md) | The scoped request for the "use soon" feature |
| [decision-record.md](decision-record.md) | The main design decision, its alternatives, and its costs |
| [handoff.md](handoff.md) | The continuation brief written when the feature landed |
| [case-study-excerpt.md](case-study-excerpt.md) | An outside-facing excerpt built from the three documents above |

## How these were produced

In the fiction, the work followed [Improve an existing project](../../workflows/improve-an-existing-project.md): the scoped request came from a planning pass, the decision was recorded while implementing, and the handoff was written at the end. The case-study excerpt was then written with only these three documents as its sources, which is why it stops where the records stop.

That last point is the one to take from this example. The excerpt does not describe how much food waste was avoided, because no record measures it. It says so instead, and says what would be needed to know.
